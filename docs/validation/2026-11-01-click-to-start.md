# 点击 EVA 快捷方式同时启动主题与 Codex

## 用户决定与基线

2026-11-01，用户确认选择“点击 EVA 快捷方式时，同时启动主题和 Codex（不依赖开机自启）”。任务分支为 `fix/reliable-login-startup`，依赖包含伴随程序现有实现的 `chore/repository-delivery`，基线 `507d592`。创建分支时工作区干净；没有从缺少这些实现的旧 main 重新开始，也没有修改官方客户端、账户或防护设置。

## 自启问题的证据

原生桌面 Status 回读显示启动项不存在、旧实例锁指向已退出进程；官方调试端口已经开放，旧快捷方式参数正确。进一步原生探针显示安装器确实写入 Run 值，0 毫秒及 200 毫秒回读正确，再等待 1000 毫秒时值为空。32/64 位原生注册表视图均未保留该值，未设置 CODEX_EVA_RUN_KEY 测试覆盖变量。火绒当天可见安全日志没有对应事件，不能断言是火绒移除。

这解释了“点击旧快捷方式打开 Codex，但没有主题”的机制。日常路径不再依赖此启动项；没有尝试用服务、计划任务、其他启动目录绕过移除行为，也没有修改防护信任。

## 当前实现

- v4 快捷方式指向 `companion/build/CodexEvaLauncher.exe`，无脚本或执行策略参数。EXE 由仓库 C# 源码使用 Windows .NET Framework 编译器生成，源文件和二进制哈希记录在本地构建收据中；用户改动二进制时拒绝覆盖。
- EXE 调用已有 `launch.ps1`；通过原生桌面助手补启伴随程序并确认实例锁及真实进程，再用官方 MSIX 执行别名打开 Codex。失败弹窗；`--diagnose` 使用同一流程，改为标准错误与退出码，便于无人值守验证。
- 已有普通模式 Codex 时报告 `CODEX_RESTART_REQUIRED`，不结束聊天。重复启动由单实例锁复用；启动器退出不终止伴随程序。
- 主题检查只读取工作台能力及可见性布尔值，不读取聊天内容。检查复用 discovery 的工作台表达式，排除隐藏、零尺寸输入框或缺少官方 bridge 的页面，避免把等待登录误报为主题失败。
- 安装、独立启动、主题检查共享 Node 查找逻辑，保留 PATH 外标准安装目录的支持。
- 旧入口按收据和哈希显式移除后创建新入口；用户改过的链接保留。卸载继续保护用户改动并清理入口、图标及 AppData 收据；仓库内 `build/` 为可复用构建产物，不作为安装数据删除。

## 真实点击验证

从真实 Explorer 桌面执行，未退出当前 Codex：

1. 通过已有停止协议退出本项目伴随程序，确认已无活动 owner。
2. ShellExecute 打开实际 `companion/Codex EVA.lnk`，自动出现新的伴随进程，主题检查返回 `ready`。
3. 再次打开相同入口，owner PID 保持不变；独立进程包身份返回 15700（无包），入口文件仍存在。
4. 全程真实 Run 项为空，Status 显示 `startupEnabled: false`、`ownerAlive: true`，证明点击补启无需登录自启。

原始派生结果与测试日志保存在忽略目录 `.cache/`，没有提交本机收据、快捷方式、编译 EXE、设置或账号数据。

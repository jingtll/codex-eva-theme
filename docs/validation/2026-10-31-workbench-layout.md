# 真实工作台边界与布局修复

依赖 `b39f863` 的独立伴随程序启动修复，在 `fix/workbench-layout` 实施。用户已确认主题出现，但背景、人物和面板整体错位。

真实页面测量显示，主题层原来覆盖整个 1796×916 窗口，而可见工作台从 x=380 开始；人物和机体纹样因此进入侧栏。页面还保留隐藏旧输入框，不能用第一个 contenteditable 作为定位依据。

修复后仅以可见输入框及其工作台定位，主题层跟随工作台 resize 和页面切换，并在输入区上方结束。装饰使用工作台容器宽度缩放，设置和仪表保持在边界内；卸载取消 observer 和待执行帧。

本机重新启动的只有伴随程序，官方客户端 PID 保持不变，没有刷新聊天。实际测量：主题层左边界 x=380，人物 x=396–696，纹样 x=396–676，主题层底部 y=786，位于输入区之上。此结果只证明当前页面几何边界，不等于所有客户端页面均已验收。

新增隔离夹具覆盖宽侧栏、隐藏旧输入框、右面板及五组窗口组合，旧代码在工作台左边界断言失败，修复后通过。布局夹具五项及基础工作台一项回归通过。全量初跑另暴露旧基础夹具未等待 viewport 改变后的布局帧；补充帧同步后该项通过，未删除点击检查。最终全量结果在后续人物可见度任务收尾时统一记录。

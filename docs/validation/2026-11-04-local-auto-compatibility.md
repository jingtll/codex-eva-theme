# 本地自动兼容验证（2026-11-04）

## 范围与基线

用户确认实现本地自动兼容，不包含联网下载适配器。分支 `feat/local-auto-compatibility` 基于本任务依赖 `fix/codex-update-compatibility` 的 `5a06b57`；开始时工作区干净。沿用当前官方执行别名和受限主页面发现，不修改官方包。

## 行为

- 静态已验证指纹继续使用原契约；未知指纹进入受限候选契约，不再整体拦截外观。指纹缺失时仅尝试外观，不发送候选内部请求。
- 用正常只读额度请求的同 ID、有效结构响应确认通道，不额外发一套重复探测请求。认证错误能确认响应通道，不能证明额度数据可用。
- 额度必须包含数值有效的额度窗口，异常格式清空显示并报告降级；刷新仍可恢复。
- 提醒必须在实际通道确认后，识别方法、非空标识、聊天来源与完成状态。读取线程元数据失败不再沿用旧来源播放提醒；未识别事件保持静默。页面重载后重新确认通道。
- 缓存仅存指纹、时间和能力布尔值，最多 8 个版本、7 天有效；损坏、过期、跨版本记录不授予能力，缓存不能绕过事件校验。退出等待缓存写入，卸载清理缓存。

## 验证

- 先观察未知指纹无法连接、未握手通知不被隔离的测试失败，再实施修复。
- Windows 宿主完整回归 110 项：109 通过、1 项跳过、0 失败。
- 独立无界面 Chrome 浏览器回归 14/14：覆盖已知/未知版本的真实 main/session/bundle、重载/暂停/恢复/清理、无关 ID/错误格式响应拒绝与正常握手、已有布局与页面可见性。
- 最终增强非空标识与重载门禁后，session 与 compatibility 针对性测试 10/10；根目录 npm test 和 node --check 通过；git diff --check 通过。
- 真实客户端热重载：首次从应用上下文发送停止请求超时，未强制结束进程；改由桌面上下文核对自有进程后使用停止协议重载，结果 companion alive=true、theme=ready。未关闭真实 Codex 或聊天。

## 边界

当前真实客户端属于已验证版本；未知版本的自动路径由真实浏览器夹具覆盖，不能证明任意未来 Codex 改版可用。真实全部提醒事件、媒体与额度精度没有在本轮全面实测。调试接入、主页面结构或内部协议发生实质变化仍可能需要人工维护。未推送、发布、合并或更改自动更新设置。

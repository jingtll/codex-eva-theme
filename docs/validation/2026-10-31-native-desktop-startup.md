# 退出 Codex 后再开无主题：原生桌面启动链路

> 2026-11-01 更新：本文是原生启动修复的历史记录。登录自启在后续实测中未能保留，用户已选择不依赖自启的[点击时同时启动方案](2026-11-01-click-to-start.md)；不要将本文旧安装回读当作当前开机验收结论。

## 已确认事实与未确认原因

用户明确本次是退出并重新打开 Codex，不是重启电脑。现场官方进程带本机调试端口，但没有 EVA 主进程；可见工作台 `skin:false`。这与上一任务“进程仍在、主题选到隐藏页”不同。

从 Explorer 启动只读桌面助手后，真实用户登录启动项为 null，锁文件记录的是已经退出的旧 PID。安装收据曾在另一数据/注册表视图显示成功，不能代替真实登录启动项验证。旧 WMI 启动测试证明了终端 Job 关闭后的生存，未覆盖用户退出 Codex 的边界；旧进程没有退出日志，因此不能断言其死亡一定由包身份继承、Job 清理或某种崩溃造成。

## 修复

- `start.ps1` 改为通过实际 Explorer 桌面的 ShellExecute 直接启动 Node。它只报告派发，不虚报已得到子 PID。
- 新 `desktop.ps1` 把 Install/Start/Status/Uninstall 交给独立原生桌面助手。助手先用 Windows API 验证当前没有包身份，再读写真实当前用户视图，避免包内注册后误报。
- 安装仍使用已有 `install.ps1` 的收据、冲突和回滚机制；真实 Run 项仍为直接 Node 命令。生产环境直接在包身份中调用低层安装脚本会报 `NATIVE_DESKTOP_REQUIRED`，隔离测试的 scratch key 不涉及真实启动项。
- 安装/启动的确认读取具有共享权限的真实锁文件，并核对对应进程确属本项目。Install 另行比较真实 Run 值与 committed 收据，检查 Windows 启动项未禁用；不擅自覆盖用户禁用选择。
- 桌面请求使用仓库 `.cache/native-desktop/` 下随机响应文件，只允许该目录内的固定命名；响应原子发布并按 UTF-8 读取，避免半写入或中文错误乱码。父调用等待确认后清理该响应文件。
- `Codex EVA.lnk` 保持直接指向官方执行别名，不重建脚本快捷方式，不修改官方包、桌宠或防护设置。

## 本机回读

原生 Install 回读真实 Run 命令为 `"C:\nvm4w\nodejs\node.exe" "E:\codex-eva-theme\companion\src\main.mjs"`，启动项启用、收据匹配、ownerAlive 为 true。

新 Node 主进程由 Explorer PID 11884 创建。进程包身份 API 返回 15700（无包），应用 ID 返回 15703（无 AUMID），符合独立伴随程序而非客户端进程的目标。这不影响官方 Codex 自身通过注册别名保留应用身份。

当前部分检查时聊天窗口处于后台，不能把某个隐藏页有皮肤等价为用户已看到主题。

## 验证边界

已增加原生 Status 的双次只读回读测试、非法响应路径拒绝测试，以及启动夹具进程无包身份断言。终端 Job 关闭生存测试继续使用临时 Node 载荷，不关闭真实 Codex。

最终仍须由用户保存工作后完全退出并重开 Codex，确认独立伴随进程仍在、可见工作台皮肤恢复；实际重启电脑后的登录自启另行验收，不能以注册表存在代替。

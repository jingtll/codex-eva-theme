# 主题出现数秒后消失：目标页面选择修复

## 现场证据

用户从 EVA 快捷方式启动 Codex，主题短暂出现后消失。只读检查发现伴随程序仍在运行，官方客户端的本机调试端口可达；不是仅凭主题消失就判定进程退出。

同一端口有两个满足已验证主页面地址规则的页面：隐藏页面上有 EVA，当前可见且有输入框的聊天页面没有 EVA。另有一个可见辅助页面没有聊天输入框，不应接入。诊断只读取页面可见性、挂载布尔值和尺寸，不读取标题或聊天内容。

`.cache/repro-visible-theme.mjs` 在真实可见聊天页上复现 `VISIBLE_WORKBENCH_LOST_THEME`。旧 `findCodexTarget` 使用 `/json/list` 的第一条匹配记录；列表顺序变化或隐藏页面排在前面时，五秒轮询可能断开当前会话，移除可见页面的皮肤，转而给隐藏页面注入。

此前按默认数据路径里的锁文件判断伴随程序是否存活，会受 MSIX 数据视图差异影响。此次使用实际进程清单核实，未把该锁诊断失败当作进程已经退出的证据。

## 修复与边界

- 保留原有官方主页面地址、page 类型及 loopback WebSocket 限制。
- 多个候选时，以有可见输入框且存在宿主桥接的页面为工作台候选，优先选择文档可见的工作台；辅助窗口不因获得焦点而被选中。
- 优先焦点工作台，其次保留当前合格目标，再按 ID 稳定选择，消除列表顺序依赖。
- 所有工作台均隐藏时允许保持会话；单个辅助探测失败不影响其他候选。当前目标短暂无法探测时可保留它，避免仅因探针错误主动卸载。
- 探针有连接/请求超时，临时 CDP 连接在 finally 中关闭。只返回布尔状态，不读取页面正文。
- 维持单会话架构：本修复不承诺同时装饰所有窗口。未修改快捷方式、真实登录启动项、官方包或两款桌宠。

## 验证

- 新目标选择测试在旧代码上失败：返回 hidden 而非 visible；稳定性测试返回 other 而非 current。修复后通过。
- 浏览器新增双页面集成测试，使用真实 CDP 探针、主循环、会话和皮肤，覆盖页面顺序颠倒、重复轮询与窗口可见性切换。
- 浏览器 10/10 通过。由于测试共享浏览器且可见性会互相影响，测试脚本改为文件串行运行，避免其他测试把需要可见的页面切到后台。
- 契约 98 项：97 通过、1 既有符号链接权限条件跳过、0 失败。
- 仅重启经进程路径核实的 EVA 伴随程序，未关闭、刷新或重启 Codex。原本失败的真实可见工作台检查恢复通过。
- 真实页面约 22 秒内五次检查均选择同一个可见工作台，皮肤已挂载、未隐藏且工作台边界就绪。该观察覆盖多个五秒轮询周期，不代表长期或开机验收。
- 双轴复核没有工程硬规则违规。需求复核发现“当前页探针超时、隐藏页探针成功”仍会转走主题，已补先失败后通过的回归并修复：没有确认可见替代页时保留当前目标。
- 用户回报：已经恢复且保持显示。补充边界修复后，经原生数据视图核对进程与锁文件，使用项目退出控制文件优雅重启伴随程序，当前可见页面检查仍通过。

## 诊断复盘

仅断言“默认选中的页面存在皮肤”会遗漏本次问题。今后的现场验收应同时检查页面可见性与输入框，并在该工作台断言皮肤可见；本次已增加目标重排的双页面集成回归。共享浏览器的可见性相关测试须串行运行，避免夹具之间抢焦点。

真实窗口后续稳定性仍以持续观察及用户反馈为准；本任务不代替开机自启和原版入口接入验收。

## 2026-10-31 启动入口取舍更新

用户明确确认“可以新增快捷方式”。允许增加 `Codex EVA` 入口，以本机调试参数启动同一个官方客户端；保留原 MSIX 入口，不改安装包、账号与聊天。该决定替代“必须仍点现有图标”的日常入口约束。

最初采用每次动态定位 MSIX 的隐藏 PowerShell 启动器，普通实例运行时提示退出。本机火绒随后明确将该 `.lnk` 判为 `TrojanDownloader/LNK.Agent.g` 并删除，项目目录也受影响。此前“未知外部机制”和“项目内入口可用”的判断失效。

用户确认继续修复后，曾改为普通快捷方式直接指向包内 `ChatGPT.exe`。后续真实反馈及 Windows API 证明该方式丢失 MSIX 包身份，造成任务栏额外分组，并被 Codex Maid Widget 的官方窗口识别规则拒绝；该路线现已撤回。

当前改用官方 MSIX 主应用注册的 `chatgpt-desktop.exe` 执行别名。隔离验证证明它同时保留官方包身份、应用 ID 和本机调试参数。新入口仍不经过脚本，伴随程序独立运行；别名缺失或注册变化时停止生成，不退回裸 exe。Windows 负责把稳定别名指向当前版本，v3 收据记录 aliasPath；旧 v1/v2 入口需移除再创建。

日常入口没有脚本层面的普通实例提示，用户需先保存并完全退出旧客户端；当前已运行的无身份进程无法原地迁移。Run 项仍直接启动 Node，手动独立启动通过本机进程管理服务。原 `launch.ps1` 仅作为可选手动诊断入口保留，并同样改用官方别名。没有修改官方包、桌宠或火绒防护。

脚本支持桌面或指定目录，实际入口仍为项目的 `companion\Codex EVA.lnk`。哈希收据保护用户修改。本轮火绒扫描 companion 目录 78 个对象、风险 0 个，扫描后新入口存在；点击启动、真实工作台及重启仍需单独验收，不能据此宣称全流程通过。
